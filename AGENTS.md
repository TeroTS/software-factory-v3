# Agent Instructions

## Repository Overview

This is an operator-led AWS Lambda MicroVM software factory PoC. The current
implementation is a local development bootstrap, not a running coding service.
The worker, AWS orchestration, and deployment resources are not implemented.

Read [DECISIONS.md](DECISIONS.md) for accepted requirements and
[README.md](README.md) for onboarding. There is no `SPEC.md` yet; use accepted
decisions for behavior until a specification is established.

## Architecture and Scope

- The approved design keeps one Codex edit–test–fix and publication invocation
  inside one MicroVM; Step Functions manages the VM lifecycle, not the agent loop.
- Gate 1 proves a real task and manual termination before Gate 2 adds
  orchestration using the same image and worker. Neither live gate has passed.
- `TeroTS/TeroTS-factory-smoke-test` is a separate demonstration repository. Its
  dependency-free calculator fixture is not this factory's development toolchain.
- Accepted decisions explicitly supersede earlier status-response shapes in the
  [source plan](docs/plans/aws-lambda-microvm-software-factory-poc.md).

## Repository Structure

- `tools/logging_smoke.py`: non-production local logging check.
- `tests/test_logging_smoke.py`: standard-library `unittest` bootstrap test.
- `Makefile`: shared setup and verification commands.
- `pyproject.toml`, `uv.lock`, `.python-version`: tooling configuration, pinned
  development dependencies, and local Python selection.
- `DECISIONS.md`, `CONTEXT.md`: accepted behavior and canonical naming.
- `docs/plans/`: proposed architecture and gate documentation.
- `docs/aws-lambda-microvms/`: copied AWS reference documentation.

## Development Workflow

Use Python 3.14, `uv`, and Make. Ruff and coverage.py are development-only
dependencies pinned in `uv.lock`; no runtime dependencies are currently declared.
Run commands from the repository root:

```sh
make setup
make verify
```

Individual commands:

```sh
make format-check
make lint
make test
make coverage
make dev
make format
```

`make format` modifies Python files; the other checks do not format source.
`make verify` runs format-check, lint, tests through coverage, and the logging
smoke check. Make uses locked installs. `uv.lock` is generated by `uv lock`;
update it only as part of an approved dependency change.

There is no type-check, build, CI, or deployment command. `make dev` is a logging
smoke check, not a server. No AWS/GitHub credentials or application environment
variables are needed for local verification. The development Python version does
not establish MicroVM runtime compatibility.

## Testing and Coverage

Tests use `unittest` discovery under `tests/`. The focused logging command and
full workflow are documented in [README.md](README.md#testing-and-coverage).
Add meaningful tests for non-trivial changes, using the existing test runner.

Coverage currently measures only `tools/`, with branch coverage and missing-line
reporting. No percentage threshold is configured. Extend the source scope when
worker code is introduced; 100% bootstrap coverage is not whole-factory coverage.
The current bootstrap logs a fixed `INFO` message to stderr; CloudWatch delivery
is not implemented.

## Domain Vocabulary

- Read `CONTEXT.md` before naming domain concepts.
- Use its canonical terms consistently in code, tests, documentation, and
  user-facing output.
- Resolve terminology conflicts before adding or renaming terms.
- Treat the accepted specification as authoritative for behavior and
  `CONTEXT.md` as authoritative for naming.
- Preserve public-interface compatibility; do not silently rename established
  CLI, JSON, or API fields.

## Commenting Convention

- Every production module and function must have a comment directly above it.
- The comment must state its purpose, key inputs/outputs, and externally visible
  effects or failure handling where applicable.
- Docstrings do not satisfy this rule.

Exemptions:

- Generated files.

## Change Guidelines

Keep changes within the accepted PoC scope and preserve the two-gate order.
Never place credentials in committed files, job input, prompts, or logs. AWS and
GitHub access requirements are in `DECISIONS.md`; local checks do not prove them.

Run the relevant focused tests and `make verify` after changes, and report actual
results and gaps. Keep README and agent guidance aligned when tooling or
interfaces change. Do not claim planned components or live gates are implemented
merely because local bootstrap verification passes.
