# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md`: canonical domain vocabulary.
- `docs/plans/`: accepted architecture decisions.

Before exploring domain concepts, read the glossary and relevant ADRs.
If they do not exist, proceed silently; create them only when terms or
decisions are resolved.

Use glossary terms consistently in code, tests, tickets, and proposals.
Flag conflicts with existing ADRs rather than silently overriding them.
